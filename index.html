Backend Principles

Principles behind my engineering decisions.

Secure by default

Authentication, authorization, validation, and error handling are treated as core system design, not afterthoughts.

Stateless where possible

Backend services should be easier to scale horizontally, with shared state handled by databases or external services.

DTO-first API contracts

Controllers should expose stable contracts and never leak internal entities or persistence models directly.

Observable and testable services

Logging, validation, exception handling, unit tests, integration tests, and performance tests improve reliability.

Restaurant Operating System

A production-oriented restaurant QR ordering platform built with Spring Boot, JavaScript, Docker Compose, Nginx, Redis, and Firebase Cloud Messaging. The system supports QR table ordering, real-time staff notifications, table sessions, order status tracking, owner statistics, and super admin operations.

The architecture was designed around stateless backend scaling, externalized state, reverse proxy routing, and stability validation through K6 soak testing.
